Hand Gesture Controlled LED System

Python + Computer Vision + Arduino

TYPEPersonal Project
FOCUSComputer Vision + Hardware
LANGUAGEPython
TOOLSOpenCV · MediaPipe · Arduino · PyFirmata2

Overview

I built this project in my first year as a hands-on way to learn Python, explore computer vision, and figure out how software running on a computer can communicate with physical hardware. The goal was simple: capture video from a webcam, work out which fingers I'm holding up, and use that information to switch individual LEDs on an Arduino on or off.

The system uses OpenCV to handle video capture, MediaPipe's hand landmark detection to locate the hand in each frame, a small piece of coordinate-based logic to interpret finger states, and PyFirmata2 to send those states to the Arduino over USB.

Each stage has a distinct role:

  • Webcam — captures the live video feed of the user's hand.
  • OpenCV — reads frames from the webcam and converts them from BGR to RGB for MediaPipe.
  • MediaPipe Hands — detects the hand in the frame and returns 21 landmark coordinates.
  • Finger Detection — my Python logic compares selected landmark coordinates and produces a five-element list: [Thumb, Index, Middle, Ring, Pinky].
  • LEDControl.py — receives the five-element list and maps each value to the corresponding Arduino pin.
  • PyFirmata2 — communicates the pin states from Python to the Arduino over USB using the Firmata protocol.
  • Arduino + LEDs — switches each LED on or off based on the received pin state.

Computer Vision

OpenCV reads frames from the webcam. Each frame arrives in BGR colour order, so the program converts it to RGB before passing it to MediaPipe — MediaPipe expects RGB input.

MediaPipe Hands processes the RGB frame and, when it detects a hand, returns 21 landmark coordinates — one for each joint and fingertip. I didn't train a model or implement any detection algorithm myself; MediaPipe provides that out of the box. My contribution was interpreting the returned landmark positions with a simple set of coordinate-based rules to decide which fingers are raised.

MediaPipe Hands provides: A list of normalised (x, y, z) positions for each of the 21 hand landmarks. The x and y values are scaled to the frame dimensions (0.0–1.0). My code reads specific landmark indices from this list and compares their coordinates — that is the extent of my computer vision work here.

Finger Detection Logic

The program builds a list of five binary values in this order:

fingers = [Thumb, Index, Middle, Ring, Pinky]
# 1 = raised,  0 = not raised

For the index, middle, ring, and pinky fingers, the code compares the y-coordinate of the fingertip landmark to the y-coordinate of the PIP joint (the proximal interphalangeal joint — the middle knuckle). Because y increases downward in image coordinates, a fingertip that is higher in the frame has a smaller y value than its PIP joint. So: 

FINGER   TIP landmark    COMPARISON landmark
Index    8               6   (PIP)
Middle   12              10  (PIP)
Ring     16              14  (PIP)
Pinky    20              18  (PIP)

CONDITION  tip.y < pip.y  →  finger raised  (append 1)
           tip.y >= pip.y →  finger down    (append 0)

The thumb is handled differently because it moves horizontally rather than vertically. The code compares the x-coordinate of the thumb tip (landmark 4) against the x-coordinate of landmark 3:

THUMB    tip = landmark 4,  comparison = landmark 3

if thumb_tip.x < thumb_pip.x:
    fingers.append(1)   # thumb extended
else:
    fingers.append(0)   # thumb not extended
Note: This is a simple coordinate-based rule, not a general-purpose pose classifier. It works well when the hand is held in a standard upright position facing the camera, but the result is orientation-dependent — tilting or rotating the hand can cause the thumb to be misclassified.

Once all five values are set, the total number of raised fingers is:

total_fingers = sum(fingers)

Software → Hardware

Once the finger states are calculated, the main script calls LEDControl.LED(fingers) inside the if results.multi_hand_landmarks: block — so LED updates happen when a hand is actually detected and the finger states have been computed. A separate LEDControl.py module handles all Arduino communication.

PyFirmata2 allows the Python program to communicate with the Arduino over USB using the Firmata protocol. When a hand is detected, the calculated finger states are sent to the Arduino, which switches the corresponding LEDs on or off.

The five LEDs are mapped to digital pins as follows (d:6:o means digital pin 6, output mode):

led_1 = board.get_pin('d:6:o')  # Thumb
led_2 = board.get_pin('d:5:o')  # Index
led_3 = board.get_pin('d:4:o')  # Middle
led_4 = board.get_pin('d:3:o')  # Ring
led_5 = board.get_pin('d:2:o')  # Pinky
Finger List index Arduino pin
Thumb fingers[0] 6
Index fingers[1] 5
Middle fingers[2] 4
Ring fingers[3] 3
Pinky fingers[4] 2

A value of 1 drives the pin high (LED on). A value of 0 drives the pin low (LED off). The order is always Thumb → Index → Middle → Ring → Pinky. For example: 

fingers = [1, 0, 1, 0, 0]
#          ↑  ↑  ↑  ↑  ↑
#       Thumb  Index  Middle  Ring  Pinky
ThumbON — pin 6
IndexOFF — pin 5
MiddleON — pin 4
RingOFF — pin 3
PinkyOFF — pin 2

Hardware

The hardware side of the project is minimal by design — the focus was on the software. The physical components are:

Arduino board — receives pin states from the computer via USB using the Firmata protocol.

5 LEDs — one per finger, wired to digital pins 2–6 with appropriate resistors.

Webcam — provides the real-time video feed that OpenCV reads frame by frame.

Computer — runs the Python script and handles all processing. The Arduino only receives the final on/off commands.

PyFirmata2 — Python library that talks to the Arduino's Firmata firmware over USB serial.

Implementation

The program runs a continuous loop: capture a frame, detect the hand, compute finger states, update the Arduino, and display feedback — all in real time.

Real-time webcam capture — OpenCV reads a new frame on every iteration of the main loop.

Hand landmark detection — MediaPipe processes the RGB frame and returns 21 landmark positions when a hand is found.

Finger-state detection — Coordinate comparisons between tip and PIP landmarks determine each finger's binary state.

Finger counting — sum(fingers) gives the total number of detected raised fingers.

Python-to-Arduino comms — PyFirmata2 communicates pin states to the Arduino over USB via Firmata. LED states are updated when a hand is detected and finger states have been calculated.

Individual LED control — Each of the five digital pins is set independently based on its finger's state value.

Real-time visual feedback — The OpenCV window draws the detected hand landmarks, finger count, current FPS, and the fingers list on the live video frame.

What I Learned

This was my first time combining Python libraries, computer vision, and physical hardware in one project. A few things I picked up along the way:

  • Working with Python libraries I hadn't used before — OpenCV, MediaPipe, and PyFirmata2 all at once.
  • How to open a webcam in OpenCV, read frames in a loop, and draw overlays such as the landmark skeleton and finger count on the live feed.
  • How MediaPipe represents a hand as a set of numbered landmark coordinates, and what each index actually refers to on the hand.
  • How to turn visual information (landmark positions) into simple logical conditions — if this coordinate is less than that coordinate, the finger is up.
  • How PyFirmata2 allows Python to control individual Arduino pins over USB without needing to write any Arduino C code.
  • Why splitting hardware control into a separate module (LEDControl.py) makes the code easier to read and debug — the vision code and the hardware code don't need to know about each other's internals.
  • What it's like to debug a real-time system where a mistake in the software immediately shows up as wrong physical behaviour — a great way to learn.
  • That a simple software decision (fingers[1] == 1) can directly switch on a physical LED — which made the connection between code and hardware feel very concrete.

Limitations & Next Steps

The finger detection uses simple coordinate comparisons rather than a pose-classification model. The rules are orientation-dependent: they work reliably when the hand is held upright and facing the camera, but different hand angles, partial occlusion, or varied lighting can all cause incorrect classifications. The current system also only controls individual LEDs — it has no debouncing or state-change filtering, so the Arduino receives an update every time a hand is detected regardless of whether the finger state actually changed.

Possible future improvements — none of which have been implemented yet:

  • Make the finger detection more reliable across different hand orientations and tilt angles.
  • Add debouncing or state-change filtering so the Arduino is not repeatedly updated when the finger state hasn't changed.
  • Handle partial occlusion and edge-of-frame positions more gracefully.
  • Improve robustness under different lighting conditions and backgrounds.
  • Support more gesture types beyond counting raised fingers.
  • Produce more useful hardware outputs — for example PWM-controlled brightness, sequences, or different actuators.
  • Improve the interface and add clearer visual feedback in the OpenCV window.
